HISTORY ITERATION

주요 개발 이력

  1. v0.1 ~ 0.3.3

    수식 스도쿠의 기본 규칙

    정답 재료 생성, 최고 점수 차액과 전문가, 후보 메모를 구성했습니다.

  2. v0.4.0 ~ 0.5.1

    브라우저 진행과 모드 분리

    서버 최종 검증과 모바일 입력을 더하고, 피드백을 받아 캐주얼을 추가했습니다.

  3. v0.5.5 ~ 0.6.0

    화면 개선에서 구조 개선으로

    반복 CSS 덮어쓰기를 정리하고 화면, 입력, 서버 및 스타일을 기능별로 나눴습니다.

  4. v0.6.1 ~ 0.6.2

    일반 숫자 오답과 검증 기준

    오답 목숨 차감을 적용하고 문구와 색상 고정값 대신 핵심 동작을 검사하도록 테스트를 정리했습니다.

  5. v0.6.3 ~ 0.6.4

    정답 잠금과 점수 설정 분리

    일반 정답은 1회 확정하고 150점을 지급합니다. 모드별 기본 점수를 공통 설정으로 옮겼습니다.

  6. v0.6.5

    진행 상태와 완료 기록 복구

    오답 메모와 이전 저장 상태를 복구하고, 미등록 결과 우선 복구 및 다른 탭의 등록 완료 확인을 보완했습니다.

82 / 지인 피드백과 모드 분리 구상

실제로 받은 피드백
1. 칸과 숫자의 색이 비슷해 구분이 힘들다.
2. 매 순간 수식을 넣는게 초반엔 신박하게 다가오지만 하다보니 불편하다.

내가 생각한 개선방안
1. 현재 우리가 잡아둔 게임의 색감이 있으니 다른 스도쿠처럼 흰색, 검은색 조합보단 배경과 숫자나 버튼의 색 톤에 대비를 준다.
2. 매 순간 수식을 넣는 방식이 추후에는 귀찮음과 불편함으로 이어질수있음을 인정하지만 무작정 수식의 칸을 줄일 경우 기존에 수식의 길이에 따라 늘어나던 점수 방식이 오히려 걸림돌이 되어 몇 개 없는 수식칸의 랜덤성 보기의 비중이 너무 높아짐 이에따라 현재 모든 칸이 수식인 게임은 챌린지 모드로 빼고, 캐주얼 모드를 추가해 각 난이도별 수식칸은 3~5칸으로 두고 나머지 빈칸은 일반 스도쿠와 동일하게 숫자를 넣는 방식으로 진행하고 해당 모드에서 수식칸은 다른 칸과 구별하기 쉽게 오른쪽 모서리에 별표시를 추가한다.

한번 보고 구상먼저 해봐

83 / 수식 칸 수와 모드별 점수 확정

캐주얼에도 전문가 난이도가 있어야해 난이도는 챌린지 모드와 똑같이 4개야 캐주얼 모드에 수식칸은 초급 3칸, 중급 4칸, 고급 5칸, 전문가 7칸으로 두고 각 3*3영역당 수식칸이 최대 1개만 들어가도록 하자 그리고 지금 챌린지 모드 점수 배율이 기본 점수 100 * (사용한 숫자 개수 + 사용한 기호 개수) 인걸로 아는데 캐주얼 모드는 기본 점수 150 * 사용한 기호 개수로 하는게 나을거같아 추가로 캐주얼 모드에 수식칸을 별표로만하면 눈에 별로 띄지 않을수있다고 했잖아 그러니까 차라리 해당 칸 테두리를 살짝 그라데이션을 넣거나해서 테마 색감을 해치지않는 선에서 테두리에 변형을 주고 별을 아예 빼자 테두리와 별 둘 다 하면 너무 보기 불편하고 별표 자체가 메모기능을 볼때도 불편해질거같아

84 / 챌린지도 연산자 최소 1개

해당 방향으로 하는게 지금 그럼 챌린지 모드도 숫자 하나만 입력이 가능한거야? 그런거면 수정해야해

CASE 02 점수와 공통 설정 / v0.6.3 ~ 0.6.5

CASE 05 수식 입력과 판정 / v0.5.1

잘못된 수식은 제출 전 입력 단계에서 차단

목표
숫자 이어 붙이기는 금지 규칙이지만 화면에서는 연속 입력이 가능해 제출할 때에야 오류를 알 수 있었습니다.
바꾼 점
잘못된 다음 재료는 버튼 단계에서 막습니다. 괄호와 연산 우선순위, 나눗셈마다 소수 부분을 버리는 계산은 유지하며 새 수식 칸에는 연산자 최소 1개를 요구합니다.
결과
