AI에 요청한 구현

공통 숫자 판정과 점수 설정, 기능별 모듈 분리 및 서버의 기록 검증을 구현하도록 요청했습니다. 최신 소스에서는 저장 상태 복구와 다중 탭 충돌, 결과 재전송도 보완했습니다.

PLAN GAME DESIGN

모든 빈칸의 수식을 일부 칸의 선택과 집중으로

모든 빈칸을 수식으로 푸는 초기 기획에서 출발했습니다. 반복 입력이 불편하다는 피드백을 받고 캐주얼을 추가하되, 기존 방식은 챌린지로 보존했습니다.

HISTORY ITERATION

주요 개발 이력

  1. v0.1 ~ 0.3.3

    수식 스도쿠의 기본 규칙

    정답 재료 생성, 최고 점수 차액과 전문가, 후보 메모를 구성했습니다.

  2. v0.4.0 ~ 0.5.1

    브라우저 진행과 모드 분리

    서버 최종 검증과 모바일 입력을 더하고, 피드백을 받아 캐주얼을 추가했습니다.

  3. v0.5.5 ~ 0.6.0

    화면 개선에서 구조 개선으로

    반복 CSS 덮어쓰기를 정리하고 화면, 입력, 서버 및 스타일을 기능별로 나눴습니다.

  4. v0.6.1 ~ 0.6.2

    일반 숫자 오답과 검증 기준

    오답 목숨 차감을 적용하고 문구와 색상 고정값 대신 핵심 동작을 검사하도록 테스트를 정리했습니다.

  5. v0.6.3 ~ 0.6.4

    정답 잠금과 점수 설정 분리

    일반 정답은 1회 확정하고 150점을 지급합니다. 모드별 기본 점수를 공통 설정으로 옮겼습니다.

  6. v0.6.5

    진행 상태와 완료 기록 복구

    오답 메모와 이전 저장 상태를 복구하고, 미등록 결과 우선 복구 및 다른 탭의 등록 완료 확인을 보완했습니다.

CASE 01 플레이 피드백 / v0.5.0

반복 수식 입력의 피로도를 두 모드로 해결

목표
모든 빈칸에 수식을 넣는 방식이 처음에는 신선하지만 반복할수록 불편하다는 지인 피드백을 받았습니다.
바꾼 점
캐주얼은 수식 칸을 3 / 4 / 5 / 7개로 줄이고 나머지는 숫자를 입력합니다. 현재 일반 정답은 150점을 한 번 지급하고 입력을 잠그며, 새 오답 입력은 목숨을 1개 줄입니다.
결과
모드와 난이도별 랭킹은 분리합니다. 같은 오답 재입력과 지우기, 메모는 목숨을 차감하지 않으며 기존 진행과 과거 랭킹도 보존합니다.

캐주얼의 수식 칸 배치와 채점

캐주얼 모드에 수식칸은 초급 3칸, 중급 4칸, 고급 5칸, 전문가 7칸으로 두고 각 3*3영역당 수식칸이 최대 1개만 들어가도록 하자 그리고 지금 챌린지 모드 점수 배율이 기본 점수 100 * (사용한 숫자 개수 + 사용한 기호 개수) 인걸로 아는데 캐주얼 모드는 기본 점수 150 * 사용한 기호 개수로 하는게 나을거같아

CASE 02 점수와 공통 설정 / v0.6.3 ~ 0.6.5

일반 정답은 한 번 지급하고, 수식은 최고점 차액만

목표
캐주얼 일반 칸을 맞혀도 점수가 오르지 않았고, 점수 기본값이 흩어져 있으면 나중에 규칙을 조정하기 어려웠습니다.
바꾼 점
일반 정답은 150점을 한 번 지급하고 잠급니다. 수식은 최고점을 넘긴 차액만 더합니다. 모드별 기본 점수는 scoring-config.js에 모으고 브라우저와 서버가 같은 계산을 사용합니다.
결과
일반 정답 중복 지급 방지, 오답 0점과 목숨 차감, 서버의 독립적인 총점 재계산을 검사했습니다. 기존 저장의 미지급 일반 칸 점수도 중복 없이 보정합니다.
  1. 일반 정답으로 150점 획득
  2. 정답 칸의 입력 잠금
  3. 다른 칸 오답 시 목숨 -1
관련 요청 발췌 (3건)

최고 점수 차액만 지급

정답을 제출해서 점수를 획득한 칸을 다시 수정할 경우 만약 수정을 해서 더 높은 점수를 얻는다면 그 차이만큼만 얻도록 할거야

일반 숫자 정답 150점

방금 플레이중에 갑자기 깨달았는데 캐주얼 모드에서 일반 빈칸을 채웠을때 점수가 안올라 일반 빈칸을 채웠을떄는 기본 점수인 150점을 지급하게 해야해

모드별 점수 설정 분리

아 그리고 지금 캐주얼이랑 챌린지 둘 다 기본 점수가 하드코딩으로 들어가있으면 추후에 내가 코드 수정으로 바로 고칠 수 있게 따로 빼줘

CASE 03 진행 저장과 검증 / v0.4.2 ~ 0.6.5

완료 기록을 보관하고 서버 확인까지 복구

목표
반복 API 호출을 줄이면서도, 통신 실패나 다중 탭 때문에 완료 기록이 사라지거나 과거 저장이 최신 상태를 덮지 않도록 해야 했습니다.
바꾼 점
플레이는 브라우저에서 처리하고 서버가 제출 이력을 재계산합니다. 미등록 공식 결과를 연습 게임보다 먼저 복구하고, 등록 전에는 새 게임 전환을 막습니다.
결과
다른 탭이 등록 후 로컬 기록을 삭제한 경우에도 성공을 확인합니다. 오답 메모 보존, 이전 저장의 잘못된 완료 상태 복구와 다중 탭 덮어쓰기 거부를 검사했습니다.
  1. 완료 결과와 시간 로컬 보관
  2. 실패 시 복구 후 검증 재요청
  3. 서버 확인 후 로컬 기록 정리
요청 발췌 / 무료 운영을 위한 서버 요청 축소

CASE 05 수식 입력과 판정 / v0.5.1

잘못된 수식은 제출 전 입력 단계에서 차단

목표
숫자 이어 붙이기는 금지 규칙이지만 화면에서는 연속 입력이 가능해 제출할 때에야 오류를 알 수 있었습니다.
바꾼 점
잘못된 다음 재료는 버튼 단계에서 막습니다. 괄호와 연산 우선순위, 나눗셈마다 소수 부분을 버리는 계산은 유지하며 새 수식 칸에는 연산자 최소 1개를 요구합니다.
결과
숫자 연속 입력과 생략된 곱셈을 막고 음수 표현은 허용하는지, 브라우저와 서버의 계산이 일치하는지 검사했습니다.
  1. 숫자 뒤 숫자 입력 차단
  2. 음수와 올바른 연산 허용
  3. 서버도 같은 규칙으로 검증

CASE 06 퍼즐 생성

목표

바꾼 점
공식 게임 시작 시 서버가 풀 수 있는 재료를 발급합니다. 재료는 기본 12개, 전문가 15개이며 각각 1회 사용합니다. v0.4부터 괄호는 별도 버튼으로 무제한 사용하고 점수에서 제외합니다.
결과
기본 12개와 전문가 15개 재료에서 정답 수식이 가능한지 검사했습니다.
관련 요청 발췌 (2건)

CASE 07 랭킹 및 관전

정상 완료 기록을 모드와 난이도별로 조회합니다. 관전에서는 칸별 최고 수식과 점수, 당시 제공된 재료를 표시하며 과거 기록은 챌린지로 유지합니다.

CASE 08 모바일 플레이 / v0.4.3 ~ 0.5.1

보드를 보면서 수식을 적는 하단 고정 입력

목표
모바일에서 보드와 수식 패널이 멀어 수식을 쓰면서 보드를 확인하기 어렵다는 직접 플레이 피드백이 있었습니다.
바꾼 점
모바일에 접이식 하단 입력 패널을 두고, 선택한 칸에 따라 숫자 패드와 수식 재료를 전환합니다. 여러 후보 숫자 메모와 게임당 무료 힌트 2회를 지원합니다.
결과
새로고침과 다중 탭 저장 충돌을 검사했습니다. 오프라인 연습은 두 모드와 4개 난이도를 지원하고 공식 랭킹에서는 제외합니다.
